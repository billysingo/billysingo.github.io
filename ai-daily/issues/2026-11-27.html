OpenAI2026-11-2301

GPT-6.2 开始进入 ChatGPT 聊天标签页

OpenAI 向 Plus、Pro、Business 和 Enterprise 逐步推出面向聊天的 GPT-6.2。

一句话锐评 · 观点

从复杂指令到联网检索，真正值得比较的是日常任务的完成质量。

背景与影响分析

官方发布说明称，新版本针对复杂请求、图像理解和信息检索进行了优化。在厂商内部评估中，图像理解得分由 GPT-6 的 47.4% 提升至 71.7%，复杂指令遵循由 62.5% 提升至 78.1%。这些数据来自厂商评估，不能直接当作所有真实任务上的提升幅度。对于普通用户，更有价值的验证方式是用相同的技术资料、截图和多约束问题进行对照测试。产品采用分批推出方式，具体可用模型和使用限制以账户实际界面为准。此次 Chat 更新也不应与 Work、Codex 模型的使用规则混为一谈。

OpenAI2026-11-2402

Codex 进入生产故障排查工作流

OpenAI 开发者博客介绍如何结合遥测、部署历史和代码分析生产问题。

一句话锐评 · 观点

让 AI 从代码生成走向证据驱动的故障分析，比直接授予生产控制权更稳妥。

背景与影响分析

官方工程文章将生产监控与代码分析联系起来：当服务发生异常时，开发者可以利用指标、日志、部署时间及代码变化缩小排查范围。该文章介绍的是工作方法，不代表所有账户都自动获得生产系统访问权限。落地时应先设置只读遥测入口，将敏感日志脱敏，并让每个故障推断关联具体证据。对于 .NET、微服务和消息队列系统，可把异常时间线、版本变更和重试记录统一整理，最后由人工确认修复方案。生产部署和关键配置修改仍应保留独立审批、回滚与审计机制。

DeepSeek2026-11-18 生效 · 计费资料补充10

DeepSeek 模型内置搜索与独立搜索 API 的计费边界

官方定价页说明模型触发的搜索与网页读取不再单独收费，返回结果仍按 Token 计费。

一句话锐评 · 观点

工具免费并不意味着整个 Agent 任务免费。

背景与影响分析

作为本期开发者参考，DeepSeek 官方价格说明指出，自北京时间 11 月 18 日中午起，模型调用触发的服务端搜索及网页读取不再单独计算工具调用费用，返回内容进入模型上下文并按模型 Token 计费。这是此前生效的计费说明，并非 11 月 27 日的新公告。应用开发者在设计搜索代理时，应区分模型内部工具和独立接口，也应考虑检索结果过长、失败重试及上下文累积带来的支出。比较不同供应商时，建议以固定任务的总成本、来源准确性、延迟和完成率为指标，而非仅比较单一 Token 价格。
